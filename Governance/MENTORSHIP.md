# Mentorship and Good-First-Issue Policy

There has been no documented mentorship or good-first-issue program. This
describes how the project supports new contributors.

## Good-first-issue labeling

- An issue is labeled `good-first-issue` when it is well-scoped, doesn't
  require deep familiarity with the codebase, has a clear acceptance
  criterion, and a maintainer is available to answer questions on it.
- Maintainers actively look for candidate issues during triage
  (`Governance/TRIAGE_POLICY.md`) rather than waiting for them to
  accumulate.
- An issue already claimed or in progress is unlabeled or marked claimed so
  new contributors don't duplicate effort.

## Mentorship

- A new contributor working a `good-first-issue` may ask questions on the
  issue itself; a maintainer or experienced contributor responds within the
  timeframe set by `Governance/REVIEW_SLA.md` where practical.
- First-time contributors get review feedback that explains the "why," not
  just the "what," so the interaction is a learning opportunity rather than
  a pass/fail gate.
- Contributors who show sustained engagement may be pointed toward larger
  issues or invited to help triage, as a path toward more involvement.

## Recognition

Contributions from the mentorship track are recognized the same way as any
other contribution, per `Governance/RECOGNITION.md`.
