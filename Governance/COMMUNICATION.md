# Communication Channels and Norms

Official channels and communication norms have been undocumented. This
lists the channels and how they're used.

## Channels

- **GitHub Issues** — the source of truth for bugs, feature requests, and
  task tracking. If it isn't in an issue, it isn't officially tracked.
- **GitHub Discussions / project chat** (Discord, Telegram, or equivalent as
  set up by the project) — real-time or semi-real-time discussion,
  onboarding questions, and community conversation. Not authoritative for
  decisions — decisions made there are written back to an issue or the
  relevant `Governance/` document.
- **Pull Requests** — code-level discussion tied to a specific change.

## Norms

- Default to public channels. Private messages to maintainers are for
  sensitive matters (security reports, code of conduct concerns) — routine
  questions belong in a public issue or channel so the answer helps others.
- Be specific: link the issue, PR, or line of code being discussed rather
  than describing it from memory.
- Assume good faith and disagree with the idea, not the person, per the
  project's code of conduct.
- Response times are best-effort, not guaranteed, outside of what
  `Governance/REVIEW_SLA.md` commits to for pull request reviews.

## Security reports

Security vulnerabilities are never reported in public issues or chat — they
follow the project's documented security disclosure process instead.
